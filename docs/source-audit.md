# Source completeness and publication audit

Current compatibility update: [Superset 1.28 review](superset-1.28.md), dated 2026-09-10, AUTO 9.9.5-public.1. The original packaging audit below is retained as provenance.

Audit date: 2026-09-09. Runtime baseline: AUTO 9.9.4.1. Public packaging revision: 9.9.4.1-public.1.

## Inputs and treatment

| Supplied source | Public treatment |
| --- | --- |
| Superset directory ZIP | Explicitly selected 23 runtime commands and two custom OpenCode plugins. Other runtime state excluded. |
| OpenCode configuration | Extracted only needed agent definitions; optional Azure endpoint and key use environment references. |
| Superset agent export | Removed machine UUIDs and home paths; tagged providers; removed permission-bypass arguments from templates. New rows receive local IDs. |
| Superset settings export | Reviewed; not imported or published. Personal UI/worktree settings are unnecessary. |
| Generic AGENTS and coding workflow documents | Condensed into portable templates and setup/workflow guides; runtime enforcement is retained. |
| Subscription/model notes | Reviewed for context; not published as account entitlements, price promises or required subscriptions. |

Excluded categories include authentication files, terminal tokens, local/host databases, terminal and conversation history, session directories, quota caches, recovery transcripts, installation backups, old patch copies, package dependencies, app-generated CLI wrappers, device state, and macOS metadata. The public repository starts with fresh history; the source ZIP is never committed.

The Azure key field in the uploaded configuration was a **reference to a local file**, not an inline API key. That file reference and the private endpoint were removed from the public configuration. No provider credential file is needed or appropriate for public setup.

## Verified upstream integration

Superset 1.27.0 was the latest release observed during this audit. The release's source was reviewed for native agent launch arguments, agent configuration fields, local agent listing, OpenCode wrapper/plugin wiring, and the host-agent database schema:

- [Release](https://github.com/superset-sh/superset/releases/tag/desktop-v1.27.0)

- [Local agent listing](https://github.com/superset-sh/superset/blob/desktop-v1.27.0/packages/cli/src/commands/agents/list/command.ts)
- [Host agent configuration](https://github.com/superset-sh/superset/blob/desktop-v1.27.0/packages/host-service/src/trpc/router/settings/agent-configs.ts)
- [Host database schema](https://github.com/superset-sh/superset/blob/desktop-v1.27.0/packages/host-service/src/db/schema.ts)
- [Managed wrappers](https://github.com/superset-sh/superset/blob/desktop-v1.27.0/packages/agent-setup/src/agent-wrappers-claude-codex-opencode.ts)

The installer uses a checked, local SQLite transaction because the reviewed CLI exposes launch/list operations rather than a general public command for adding these configured host-agent rows. This is version-coupled integration. It requires Superset to be stopped, fails on an unknown schema, and never replaces the complete database.

## Limits of the audit

The included scan checks known token/key patterns, literal credential fields in JSON, private/generated file types, symlinks, and personal home paths. Source selection and review are the primary privacy controls; pattern scanning cannot prove the absence of every possible secret. The uploaded private backup itself is not sanitized in place.

Offline validation covers syntax, JSON/configuration structure, route/template references, installation idempotence and rollback, preservation of unrelated state, conflict rejection, disabled-provider cache filtering, and exact recovery completion evidence. It does not exercise real Superset, provider authentication, macOS Keychain, quota APIs, terminal disposal, or actual Free → Go transitions.
